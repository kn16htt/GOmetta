# GOmetta — мессенджер для Telegram

**GOmetta** — мессенджер, который работает **только через Telegram**. Номер телефона подтверждается одним касанием внутри Telegram Mini App: без SMS, без кодов из СМС и без ручного ввода номера.

- Сайт: чистые HTML/CSS/JS, без сборки.
- Сервер: Python + SQLite, только стандартная библиотека.
- Доставка сообщений: HTTP long-polling.
- Вход: Telegram Mini App → «Подтвердить номер» → аккаунт создан.

---

## Как это работает

1. Пользователь открывает GOmetta из Telegram-бота (Mini App).
2. Нажимает «Подтвердить номер».
3. Telegram сам передаёт номер через `requestContact`.
4. Сервер проверяет подпись `initData` (если задан токен бота), находит или создаёт аккаунт и выдаёт токен сессии.
5. Дальше — обычная переписка с друзьями, которые тоже вошли через Telegram.

На сайте вне Telegram показывается кнопка «Открыть GOmetta в Telegram» — вход по номеру и SMS полностью убран.

---

## Что уже работает

- **Вход только через Telegram** — без телефона, SMS и PIN-кодов.
- **Реальная переписка** между разными людьми и устройствами через общий сервер.
- **Чаты**: создание по номеру друга, список с последним сообщением, временем и непрочитанными.
- **Сообщения**: доставка в реальном времени, статусы «отправлено/прочитано», группировка по дням.
- **Поиск** по именам чатов и тексту сообщений.
- **Настройки**: имя, username, тема, уведомления, выход.
- **PWA**: manifest и service worker (офлайн-кеш статики, установка на домашний экран).
- **Звонки**: пока имитация (интерфейс и история), медиа не передаётся.

## Настройка Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) и создайте бота: `/newbot`.
2. Задайте Mini App: `/newapp` (или **Bot Settings → Menu Button**).
   - URL — адрес, где развёрнут GOmetta (обязательно HTTPS).
   - Например: `https://your-service.onrender.com/`.
3. Сохраните:
   - **имя бота** (без `@`) — переменная `GOMETTA_BOT`;
   - **токен бота** — переменная `GOMETTA_BOT_TOKEN`.

`GOMETTA_BOT` нужен, чтобы сайт показал ссылку на бота. `GOMETTA_BOT_TOKEN` включает проверку подписи `initData` на сервере — **обязательно для публичного запуска**.

## Быстрый старт локально

Нужен Python 3.10+.

```bash
cd gometta
py server.py          # Windows
# или
python server.py      # Linux / macOS
```

Сервер отдаёт и сайт, и API: **http://127.0.0.1:8099**.

Переменные окружения:

```powershell
# Windows PowerShell
$env:HOST='127.0.0.1'
$env:PORT='8099'
$env:GOMETTA_BOT='your_bot'
$env:GOMETTA_BOT_TOKEN='123456:ABC...'
py server.py
```

```bash
# Linux / macOS
HOST=127.0.0.1 PORT=8099 GOMETTA_BOT=your_bot GOMETTA_BOT_TOKEN=123456:ABC... python server.py
```

> Telegram Mini App требует публичный HTTPS-адрес. Для локальной проверки используйте туннель (Cloudflare Tunnel, ngrok) и укажите его URL в BotFather. Без Telegram-клиента сайт покажет только кнопку «Открыть GOmetta в Telegram».

## Развёртывание

### Вариант A. Всё на Render (проще всего)

1. Загрузите папку `gometta` в репозиторий GitHub.
2. В [Render](https://render.com) создайте **New → Web Service** и подключите репозиторий.
3. Укажите:
   - **Root Directory**: `gometta` (если в репозитории лежит вся папка);
   - **Runtime**: Python;
   - **Build Command**: `pip install -r requirements.txt`;
   - **Start Command**: `python server.py`.
4. Добавьте переменные окружения:
   - `HOST=0.0.0.0`;
   - `GOMETTA_BOT=your_bot`;
   - `GOMETTA_BOT_TOKEN=123456:ABC...`.
5. Откройте выданный HTTPS-адрес и укажите его как URL Mini App в BotFather.

Важно про бесплатный тариф Render:

- сервис «засыпает» после простоя, первый запрос может идти 30–60 секунд;
- файловая система временная, поэтому SQLite-база может обнулиться при перезапуске или деплое;
- для постоянного хранения подключите Render Disk (платно) или внешнюю БД.

### Вариант B. GitHub Pages + сервер на Render

1. Разверните сервер по варианту A.
2. В `config.js` укажите адрес сервера:

```js
window.GOMETTA_API = 'https://your-service.onrender.com';
```

3. Выложите статические файлы на GitHub Pages (**Settings → Pages → Deploy from a branch → main / root**).
4. URL Mini App в BotFather можно оставить как адрес Render — так надёжнее: вход всё равно происходит внутри Telegram.

CORS на сервере разрешён, поэтому сайт с GitHub Pages сможет обращаться к Render.

## Настройка `config.js`

```js
window.GOMETTA_API = '';          // демо-режим без сервера
window.GOMETTA_API = 'https://your-service.onrender.com'; // внешний backend
window.GOMETTA_BOT = 'your_bot';  // необязательно: сервер отдаёт имя через /api/config
```

Если `GOMETTA_API` не задан:

- `http://127.0.0.1`, `http://localhost` и обычный домен — API берётся с того же origin;
- `file://` и `*.github.io` — включается демо-режим без сервера.

Демо-режим показывает интерфейс, но вход не работает: нужен сервер и Telegram-бот.

## Структура проекта

```
gometta/
├── index.html        # разметка: вход через Telegram, чаты, настройки, звонки
├── styles.css        # темы, адаптивная вёрстка, анимации
├── app.js            # интерфейс + клиент API + long-polling
├── config.js         # адрес backend и имя бота
├── server.py         # сервер: API, SQLite, Telegram initData, статика
├── sw.js             # service worker (не кеширует /api/)
├── manifest.json     # PWA-манифест
├── icon.svg          # иконка
├── requirements.txt  # зависимостей нет (только stdlib)
├── Procfile          # команда запуска для Render/Heroku
└── README.md
```

Файл базы `gometta.db` создаётся рядом с `server.py` при первом запуске. В git его добавлять не нужно.

## API

Все защищённые запросы передают заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/config` | имя Telegram-бота для кнопки входа |
| POST | `/api/auth/telegram` | вход/регистрация по номеру из Telegram (`initData`) |
| GET | `/api/state?since=N&timeout=25` | состояние и long-poll новых сообщений |
| GET | `/api/me` | текущий пользователь |
| PATCH | `/api/me` | изменить имя/username |
| POST | `/api/chats` | создать чат по номеру друга |
| POST | `/api/chats/{id}/messages` | отправить сообщение |
| POST | `/api/chats/{id}/read` | отметить чат прочитанным |
| POST | `/api/chats/{id}/clear` | очистить историю |
| DELETE | `/api/chats/{id}` | удалить чат |
| POST | `/api/logout` | отозвать токен |

`/api/state` возвращает `version`. Клиент передаёт её в `since`, и сервер держит соединение, пока версия не изменится (до 25 секунд). Так сообщения приходят почти мгновенно без WebSocket.

## Безопасность и ограничения

Что уже сделано:

- проверка подписи Telegram `initData` (HMAC-SHA256) при заданном `GOMETTA_BOT_TOKEN`;
- токены сессий случайные, хранятся в БД;
- SQL-запросы параметризованы;
- CORS и проверка членства в чате;
- service worker не кеширует `/api/`, чтобы long-polling не ломался.

Что нужно добавить для публичного продакшена:

- **обязательно** задать `GOMETTA_BOT_TOKEN`, иначе сервер доверяет данным клиента;
- ограничение частоты запросов и защита от перебора;
- HTTPS (Render даёт его автоматически);
- постоянную БД (Render Disk или PostgreSQL);
- резервное копирование и модерацию;
- при необходимости — end-to-end шифрование.

Ограничения текущей версии:

- звонки имитируются, медиа не передаётся;
- групп, вложений, реакций и push-уведомлений пока нет;
- вход возможен только внутри Telegram; обычный браузер показывает ссылку на бота;
- при потере доступа к Telegram восстановление аккаунта не предусмотрено.
